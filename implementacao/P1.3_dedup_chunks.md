# P1.3 — Dedup pós-merge entre chunks (Engenheiro e Orçamentista)

**Prioridade:** P1
**Tipo:** fix
**Branch:** `fix/p1-3-dedup-chunks`
**Esforço estimado:** 2-3 dias
**Depende de:** P0.4 (chunking padronizado no Auditor)

## Objetivo

Adicionar etapa de detecção de duplicatas após o merge dos chunks no Engenheiro Técnico e no Orçamentista. Hoje, quando o memorial ou o orçamento é grande o suficiente para acionar chunking, item que aparece em mais de um chunk vai dobrado para os próximos agentes.

## Contexto

`server/agents/chunking.ts` define `mergeEngenheiroOutputs(outputs[])` que concatena os arrays de itens dos chunks sem revalidar duplicatas. Mesmo problema em `server/agents/budgetChunking.ts` com `mergeOrcamentistaOutputs(outputs[])`.

Casos típicos:
- Memorial fala de "instalação elétrica completa" no início e detalha "pontos de tomada", "quadros de luz" no meio. Se o split corta entre os dois, o pacote global vai num chunk e os componentes em outro — sem comunicação entre eles, o item pai e os filhos viram irmãos somáveis.
- Orçamentista divide em frentes ("Estrutura", "Instalações"). Item ambíguo ("ponto de luz na laje") pode ser classificado em ambas as frentes pela LLM e ir duas vezes.

Solução: implementar `dedupItems()` puro determinístico que normaliza descrições e detecta sobreposições.

## Lógica de dedup

```ts
// server/agents/dedupUtils.ts

export interface DedupableItem {
  description: string;
  unit?: string;
  category?: string;
  quantity?: number;
  itemNumber?: string;
}

export function normalizeDescription(s: string): string {
  return s
    .toLowerCase()
    .normalize('NFD')
    .replace(/[̀-ͯ]/g, '')   // remove acentos
    .replace(/[^a-z0-9\s]/g, ' ')      // só letras, números e espaço
    .replace(/\s+/g, ' ')
    .trim();
}

/**
 * Distância de Jaccard entre dois conjuntos de tokens.
 * Retorna 0..1 (1 = idêntico).
 */
export function tokenSimilarity(a: string, b: string): number {
  const tokensA = new Set(normalizeDescription(a).split(' ').filter(t => t.length > 2));
  const tokensB = new Set(normalizeDescription(b).split(' ').filter(t => t.length > 2));
  if (tokensA.size === 0 && tokensB.size === 0) return 1;
  const intersection = new Set([...tokensA].filter(t => tokensB.has(t)));
  const union = new Set([...tokensA, ...tokensB]);
  return intersection.size / union.size;
}

export interface DedupResult<T> {
  items: T[];
  duplicatesRemoved: Array<{ keeperIndex: number; removedIndex: number; reason: string; similarity: number }>;
}

/**
 * Detecta itens duplicados em uma lista. Política de empate:
 * - Mesma descrição normalizada + mesma unidade → duplicata exata, manter o de maior quantidade.
 * - Similaridade ≥ 0.85 + mesma unidade + mesma categoria → duplicata provável, manter o primeiro e logar.
 * - Similaridade entre 0.65 e 0.85 → suspeita, NÃO remover, só logar para revisão.
 */
export function dedupItems<T extends DedupableItem>(
  items: T[],
  options: { strictThreshold?: number; suspectThreshold?: number } = {},
): DedupResult<T> {
  const strictThreshold = options.strictThreshold ?? 0.85;
  const suspectThreshold = options.suspectThreshold ?? 0.65;

  const result: T[] = [];
  const removed: DedupResult<T>['duplicatesRemoved'] = [];
  const indexed: Array<{ item: T; normalized: string; originalIndex: number }> =
    items.map((item, originalIndex) => ({
      item,
      normalized: normalizeDescription(item.description),
      originalIndex,
    }));

  const consumed = new Set<number>();

  for (let i = 0; i < indexed.length; i++) {
    if (consumed.has(i)) continue;
    let keeper = indexed[i];

    for (let j = i + 1; j < indexed.length; j++) {
      if (consumed.has(j)) continue;
      const candidate = indexed[j];

      // Pré-filtro: mesma unidade (se ambos têm) e mesma categoria (se ambas têm)
      if (keeper.item.unit && candidate.item.unit && keeper.item.unit !== candidate.item.unit) continue;
      if (keeper.item.category && candidate.item.category && keeper.item.category !== candidate.item.category) continue;

      // Match exato por descrição normalizada
      if (keeper.normalized === candidate.normalized) {
        // Manter o de maior quantidade
        if ((candidate.item.quantity ?? 0) > (keeper.item.quantity ?? 0)) {
          consumed.add(keeper.originalIndex);
          removed.push({ keeperIndex: candidate.originalIndex, removedIndex: keeper.originalIndex, reason: 'exact_match', similarity: 1 });
          keeper = candidate;
        } else {
          consumed.add(candidate.originalIndex);
          removed.push({ keeperIndex: keeper.originalIndex, removedIndex: candidate.originalIndex, reason: 'exact_match', similarity: 1 });
        }
        continue;
      }

      const sim = tokenSimilarity(keeper.normalized, candidate.normalized);

      if (sim >= strictThreshold) {
        // Remover candidato, manter keeper (primeiro a aparecer)
        consumed.add(candidate.originalIndex);
        removed.push({ keeperIndex: keeper.originalIndex, removedIndex: candidate.originalIndex, reason: 'high_similarity', similarity: sim });
      } else if (sim >= suspectThreshold) {
        // Apenas logar — não remover
        removed.push({ keeperIndex: keeper.originalIndex, removedIndex: candidate.originalIndex, reason: 'suspect_only_logged', similarity: sim });
      }
    }

    result.push(keeper.item);
  }

  return { items: result, duplicatesRemoved: removed };
}
```

import { describe, it, expect } from 'vitest';
import { normalizeDescription, tokenSimilarity, dedupItems } from './agents/dedupUtils';

describe('normalizeDescription', () => {

describe('dedupItems', () => {

## Observações

- O ajuste fino dos thresholds (0.85 e 0.65) precisa ser validado contra orçamentos reais. Comece com esses valores e revise depois de processar 10-20 obras.
- Esta solução é determinística e barata — roda em milissegundos. P2.6 propõe estender o mesmo algoritmo para o Auditor (substituindo o detector de duplicatas via LLM).
- Item PAI (`isSummaryItem=true`) com filhos não deve ser removido por similaridade com filho — o algoritmo já preserva isso porque usa `tokenSimilarity` sobre descrição normalizada e a relação pai/filho é estrutural, não textual. Mas vale rodar um teste com plano hierarquizado ("Sistema VRF" + "Condensadora VRF" + "Fan coils VRF") para confirmar que apenas o duplicado entre chunks é removido.

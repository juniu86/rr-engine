## Schema proposto

```ts
export const priceDatabaseEntries = mysqlTable('price_database_entries', {
  id: bigint('id', { mode: 'number' }).primaryKey().autoincrement(),
  source: varchar('source', { length: 20 }).notNull(), // 'sinapi' | 'pini'
  code: varchar('code', { length: 50 }).notNull(),
  description: text('description').notNull(),
  unit: varchar('unit', { length: 20 }).notNull(),
  price: decimal('price', { precision: 12, scale: 4 }).notNull(),
  state: varchar('state', { length: 5 }), // SP, RJ, etc.
  category: varchar('category', { length: 100 }),
  referenceDate: date('reference_date').notNull(),
  componentsJson: json('components_json'), // decomposição mão de obra/material/equipamento
  scrapedAt: timestamp('scraped_at').defaultNow().notNull(),
  isActive: boolean('is_active').default(true).notNull(),
}, (t) => ({
  sourceCodeIdx: uniqueIndex('uq_source_code_state_date').on(t.source, t.code, t.state, t.referenceDate),
  searchIdx: index('idx_search').on(t.source, t.state, t.isActive),
  descIdx: index('idx_description').on(t.description),
}));
```

`uniqueIndex` permite ter múltiplas versões da mesma composição em datas diferentes (ex.: SINAPI 87529 SP Jan/2025 e SINAPI 87529 SP Mar/2026). Apenas a mais recente fica `isActive=true`.

## Implementação — repo

```ts
// server/services/priceDatabaseRepo.ts

import { db } from '../db';
import { priceDatabaseEntries } from '../../drizzle/schema';
import { and, eq, desc, sql } from 'drizzle-orm';

export interface PriceEntry {
  source: 'sinapi' | 'pini';
  code: string;
  description: string;
  unit: string;
  price: number;
  state?: string;
  category?: string;
  referenceDate: Date;
  components?: Array<{ description: string; unit: string; coefficient: number; unitCost: number }>;
}

export async function upsertPriceEntry(entry: PriceEntry): Promise<void> {
  await db.insert(priceDatabaseEntries).values({
    source: entry.source,
    code: entry.code,
    description: entry.description,
    unit: entry.unit,
    price: entry.price.toFixed(4),
    state: entry.state ?? null,
    category: entry.category ?? null,
    referenceDate: entry.referenceDate,
    componentsJson: entry.components ?? null,
  }).onDuplicateKeyUpdate({
    set: {
      price: entry.price.toFixed(4),
      description: entry.description,
      componentsJson: entry.components ?? null,
      scrapedAt: new Date(),
    },
  });
}

export async function getActivePriceEntries(source: 'sinapi' | 'pini', state?: string) {
  const conditions = [eq(priceDatabaseEntries.source, source), eq(priceDatabaseEntries.isActive, true)];
  if (state) conditions.push(eq(priceDatabaseEntries.state, state));
  return db.select().from(priceDatabaseEntries).where(and(...conditions));
}

export async function deactivateOldEntries(source: 'sinapi' | 'pini', newReferenceDate: Date): Promise<number> {
  const result = await db.update(priceDatabaseEntries)
    .set({ isActive: false })
    .where(and(
      eq(priceDatabaseEntries.source, source),
      sql`${priceDatabaseEntries.referenceDate} < ${newReferenceDate}`,
      eq(priceDatabaseEntries.isActive, true),
    ));
  return result.affectedRows ?? 0;
}
```

## Observações

- TCPOWeb (PINI oficial) requer assinatura paga. Se não houver autorização, considerar fontes alternativas como o site da Editora PINI com partial scraping de tabelas públicas, ou fontes sucedâneas (CCB, IRENE-RJ, IBAPE-RJ). Documentar a fonte escolhida.
- Adicionar coluna `dataSource` na tabela apontando para origem da última atualização (ex.: `orcamentor.com`, `tcpoweb.com.br`, `manual_seed`) ajuda a auditar mudanças.
- O `node-cron` roda dentro do processo Node — em deploy multi-instância, pode disparar duplicado. Para esta fase ainda em Manus, é aceitável; em fase de migração para fora, trocar por orquestrador externo (GitHub Actions agendado, Cloud Scheduler).
- Considerar adicionar UI em Settings → Empresa mostrando "Última atualização SINAPI: dd/mm/aaaa" para transparência.
- O caso "código existe mas o site mudou layout" é comum em scraping. O job precisa marcar a entrada como "stale" em vez de falhar silencioso.

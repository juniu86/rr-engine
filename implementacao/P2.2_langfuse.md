# P2.2 — Observabilidade externa (Langfuse)

**Prioridade:** P2
**Tipo:** feat
**Branch:** `feat/p2-2-langfuse`
**Esforço estimado:** 2-3 dias
**Depende de:** P0.3 (telemetria interna)

## Objetivo

Plugar Langfuse no wrapper `invokeLLM` para ganhar visualização de chains, comparação entre execuções, debug de prompts e métricas agregadas. P0.3 cobre persistência interna de tokens; P2.2 cobre debugging operacional do dia a dia.

## Contexto

Hoje o produto tem winston/console e (após P0.3) tabela `agent_executions` no banco. Falta:
- Visualizar a sequência de 10 agentes de um orçamento como árvore.
- Comparar execuções de dois projetos lado a lado.
- Identificar prompts que mais alucinam ou demoram.
- Monitorar custo agregado por dia/semana fora do banco.

Langfuse cobre tudo isso e tem free tier generoso (50k events/mês). Self-hosting é opção também — Langfuse é open source.

Alternativas consideradas:
- **OpenLLMetry** (OpenTelemetry para LLMs) — mais aberto, integra com qualquer backend, mas curva de aprendizado maior.
- **LangSmith** — paywall mais cedo.
- **Helicone** — proxy-based, exige reroteamento de tráfego.

Recomendação: **Langfuse**, hospedado no cloud deles inicialmente. Migrar para self-hosted quando volume justificar.

## Implementação

### 1. Inicialização

```ts
// server/services/tracing.ts (novo)

import { Langfuse } from 'langfuse';
import { ENV } from '../_core/env';

let client: Langfuse | null = null;

export function getLangfuse(): Langfuse | null {
  if (!ENV.langfuseEnabled) return null;
  if (!client) {
    client = new Langfuse({
      publicKey: ENV.langfusePublicKey,
      secretKey: ENV.langfuseSecretKey,
      baseUrl: ENV.langfuseHost,
    });
  }
  return client;
}

export async function shutdownTracing() {
  await client?.shutdownAsync();
}
```

### 2. Trace por orçamento (em `routers.ts`)

```ts
import { getLangfuse } from './services/tracing';

// dentro do procedure que orquestra o pipeline:
const langfuse = getLangfuse();
const trace = langfuse?.trace({
  name: 'orcamento_pipeline',
  userId: ctx.userId.toString(),
  metadata: {
    projectId: project.id,
    projectName: project.name,
  },
});

try {
  for (const agentType of agentSequence) {
    const span = trace?.span({ name: `agent.${agentType}` });
    try {
      const output = await agent.execute(input);
      span?.end({ output: { totalKeys: Object.keys(output ?? {}).length } });
    } catch (e) {
      span?.end({ level: 'ERROR', statusMessage: String(e) });
      throw e;
    }
  }
  trace?.update({ output: { status: 'completed' } });
} finally {
  await langfuse?.flushAsync();
}
```

### 3. Span por chamada LLM (em `_core/llm.ts`)

```ts
export async function invokeLLM(params: InvokeParams): Promise<InvokeResult> {
  const langfuse = getLangfuse();
  const generation = langfuse?.generation({
    name: `llm.${params.model}`,
    model: params.model ?? 'unknown',
    modelParameters: {
      temperature: params.temperature,
      maxTokens: params.max_tokens ?? params.maxTokens,
    },
    input: params.messages,
  });

  const t0 = Date.now();
  try {
    const result = await /* lógica atual de fetch */;
    generation?.end({
      output: result.choices?.[0]?.message,
      usage: {
        promptTokens: result.usage?.prompt_tokens,
        completionTokens: result.usage?.completion_tokens,
        totalTokens: result.usage?.total_tokens,
      },
    });
    return result;
  } catch (err) {
    generation?.end({
      level: 'ERROR',
      statusMessage: String(err),
    });
    throw err;
  }
}
```

## Observações

- Langfuse cloud free tier (50k events/mês). Cada orçamento gera ~10 generations + 1 trace = ~11 events. Free tier suporta ~4.500 orçamentos/mês.
- Considerar self-hosting Langfuse Docker em fase de migração para fora do Manus — Langfuse é open source.
- O `userId` enviado ao Langfuse é o ID interno. Se quiser correlação com customer no Stripe, adicionar tag adicional.
- Após acumular dados, criar saved views úteis: "Orçamentos com falha", "Agentes mais lentos", "Custo por dia da semana".
- A combinação P0.3 (banco interno) + P2.2 (Langfuse externo) é redundante intencionalmente. Banco serve para queries ad-hoc e para análise de unit economics (Claude faz JOIN com Stripe). Langfuse serve para debugging visual e operação do dia a dia.

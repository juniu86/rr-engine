# P2.4 — Streaming de resposta no pipeline

**Prioridade:** P2
**Tipo:** feat
**Branch:** `feat/p2-4-streaming`
**Esforço estimado:** 5-8 dias
**Depende de:** concluir P0

## Objetivo

Habilitar streaming nas chamadas LLM e mostrar resultados parciais por agente no frontend. Hoje o usuário espera 2 a 5 minutos sem feedback granular além do "Engenheiro Técnico — em execução". Streaming melhora drasticamente a UX percebida e permite cancelamento parcial.

## Contexto

`server/_core/llm.ts` faz `fetch` non-streaming na Forge da Manus e em Anthropic direta. Anthropic API e Gemini API suportam streaming via Server-Sent Events. O Forge da Manus suporta streaming também (verificar).

Componente `client/src/components/AgentProgressPipeline.tsx` mostra o status dos 10 agentes mas não recebe parciais. Mudar para receber updates incrementais.

A mudança é em duas camadas:
1. Backend: `invokeLLM` ganha modo streaming, e cada agente publica eventos (tokens chegando, agente concluindo).
2. Frontend: tRPC subscription ou WebSocket para receber eventos.

## Arquivos a tocar

- `server/_core/llm.ts` — adicionar `invokeLLMStream(params)`
- `server/agents/index.ts` — opcionalmente, novo método `_executeStreaming`
- `server/routers.ts` — substituir procedure `query`/`mutation` por `subscription` para o pipeline
- `server/_core/trpc.ts` — adicionar configuração de subscription (necessita WebSocket)
- `client/src/components/AgentProgressPipeline.tsx` — consumir subscription
- `client/src/pages/NewProject.tsx` — usar componente atualizado
- `client/src/lib/trpc.ts` — habilitar `wsLink` para subscriptions

## Decisão técnica

**tRPC subscriptions vs Server-Sent Events vs WebSocket nativo:**

- **tRPC subscription** (recomendado): mantém type-safety, integra com o resto do código.
- **SSE**: mais simples, mas menos integrado.
- **WebSocket**: mais flexível, mais complexo.

Recomendação: **tRPC subscription** com WebSocket transport. Já temos tRPC em todo lugar, vale a pena estender.

## Implementação

### 1. Streaming no `invokeLLM`

```ts
// server/_core/llm.ts (adicionar)

export interface StreamEvent {
  type: 'token' | 'complete' | 'error';
  delta?: string;
  finishReason?: string;
  error?: string;
  usage?: { promptTokens: number; completionTokens: number; totalTokens: number };
}

export async function* invokeLLMStream(params: InvokeParams): AsyncGenerator<StreamEvent> {
  // ... montar payload com stream: true
  const response = await fetch(/* ... */, { /* ... */, body: JSON.stringify({ ...payload, stream: true }) });
  const reader = response.body!.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });

    const lines = buffer.split('\n');
    buffer = lines.pop() ?? '';

    for (const line of lines) {
      if (!line.startsWith('data: ')) continue;
      const data = line.slice(6).trim();
      if (data === '[DONE]') {
        yield { type: 'complete' };
        return;
      }
      try {
        const parsed = JSON.parse(data);
        const delta = parsed.choices?.[0]?.delta?.content;
        if (delta) yield { type: 'token', delta };
        if (parsed.choices?.[0]?.finish_reason) {
          yield { type: 'complete', finishReason: parsed.choices[0].finish_reason, usage: parsed.usage };
        }
      } catch {}
    }
  }
}
```

### 2. Subscription no router

```ts
// server/routers.ts (procedure novo)

generateProject: t.subscription
  .input(z.object({ projectId: z.number() }))
  .subscription(async function* ({ input, ctx }) {
    yield { type: 'start', projectId: input.projectId };

    for (const agentType of agentSequence) {
      yield { type: 'agent_start', agent: agentType };

      const agent = agents[agentType];
      const agentInput = /* ... */;

      // Variante streaming: emitir tokens conforme chegam
      let buffer = '';
      for await (const event of agent.executeStreaming(agentInput)) {
        if (event.type === 'token') {
          buffer += event.delta;
          // Não enviar cada token — agrupar em chunks de N caracteres ou X ms
          yield { type: 'agent_partial', agent: agentType, preview: buffer.slice(0, 200) };
        }
        if (event.type === 'complete') {
          yield { type: 'agent_complete', agent: agentType, output: event.parsedOutput };
        }
      }
    }

    yield { type: 'pipeline_complete' };
  }),
```

## Observações

- Streaming aumenta complexidade. Avaliar custo/benefício caso o produto rode bem com a UX atual e P0.3 já mostre tempos razoáveis.
- Há uma alternativa intermediária: mostrar status mais detalhado por etapa do agente, sem streaming token-a-token. Ex.: "Engenheiro Técnico — analisando 80 itens (32/80)". Custa muito menos para implementar.
- Se a fase de migração para fora do Manus mudar a stack (ex.: Next.js + edge functions), o desenho de streaming pode mudar bastante. Considere fazer P2.4 só após decidir o stack final.

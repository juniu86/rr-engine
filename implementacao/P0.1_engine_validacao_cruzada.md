# P0.1 — Plugar `deterministicEngine` como camada de validação cruzada

**Prioridade:** P0
**Tipo:** feat
**Branch:** `feat/p0-1-engine-validacao-cruzada`
**Esforço estimado:** 5-8 dias
**Depende de:** P0.3 (telemetria — para medir o custo da camada extra)

## Objetivo

Religar o motor determinístico que existe em `server/lib/deterministicEngine/` como **segunda fonte independente de orçamento**. O Auditor compara o total LLM com o total determinístico — divergência maior que X% dispara alerta. Esse é o débito mais grave do produto: hoje a única defesa contra alucinação dos agentes LLM é o `priceAnchorValidator` que compara apenas 15 itens.

## Contexto

O motor determinístico está completo em `server/lib/deterministicEngine/`:

- `index.ts` exporta `processMemorial(markdown, configOverrides?, llmTotal?)` que executa parser → pricing → logistics → budget → crossValidation
- `modules/parser.ts` — extrai itens do markdown
- `modules/pricing.ts` — precifica usando `config/sinapi-precos.ts`
- `modules/logistics.ts` — calcula custos indiretos
- `modules/budget.ts` — consolida o orçamento
- `modules/crossValidation.ts` — já tem código de cross-check (vou validar se serve direto)

Grep em `server/`: `processMemorial` é importado **apenas** em `server/sprint2-3-improvements.test.ts`. Ou seja, nada em produção chama. O código está testado mas desligado.

A implementação consiste em:
1. Rodar o engine em paralelo aos agentes durante o pipeline.
2. Persistir o output em uma nova tabela `deterministic_engine_runs`.
3. Passar o total determinístico ao Auditor para comparação.
4. Adicionar regra no Auditor: divergência maior que 15% → severity `critical`; entre 5% e 15% → severity `warning`; menor que 5% → `info`.

## Arquivos a tocar

- `server/routers.ts` — invocar `processMemorial` no pipeline, salvar resultado, passar ao Auditor

  ```ts
  import { processMemorial } from '../lib/deterministicEngine';
  import { db } from '../db';
  import { deterministicEngineRuns } from '../../drizzle/schema';
  import { logger } from '../utils/logger';

  export interface DeterministicResult {
    totalBaseCost: number;
    totalDirectCost: number;
    totalLogisticsCost: number;
    totalItemsParsed: number;
    warnings: string[];
    raw: any;
    latencyMs: number;
  }

  export async function runDeterministicValidator(
    projectId: number,
    memorialMarkdown: string,
    llmTotalForReference?: number,
  ): Promise<DeterministicResult> {
    const t0 = Date.now();
    let result: DeterministicResult;
    try {
      const out = processMemorial(memorialMarkdown, undefined, llmTotalForReference);
      result = {
        totalBaseCost: out.totalBaseCost ?? 0,
        totalDirectCost: out.totalDirectCost ?? 0,
        totalLogisticsCost: out.totalLogisticsCost ?? 0,
        totalItemsParsed: out.itens?.length ?? 0,
        warnings: out.warnings ?? [],
        raw: out,
        latencyMs: Date.now() - t0,
      };
    } catch (err) {
      logger.error('Deterministic engine failed', { error: err, projectId });
      throw err;
    }

    await db.insert(deterministicEngineRuns).values({
      projectId,
      totalDirectCost: result.totalDirectCost.toFixed(2),
      totalLogisticsCost: result.totalLogisticsCost.toFixed(2),
      totalBaseCost: result.totalBaseCost.toFixed(2),
      totalItemsParsed: result.totalItemsParsed,
      warningsJson: result.warnings,
      rawOutputJson: result.raw,
      llmTotal: null, // será atualizado depois do Auditor
      divergencePercent: null,
      divergenceClass: null,
      latencyMs: result.latencyMs,
    });

    return result;
  }

  export async function recordDivergence(
    projectId: number,
    deterministicTotal: number,
    llmTotal: number,
  ) {
    const divergence =
      llmTotal > 0
        ? Math.abs((llmTotal - deterministicTotal) / llmTotal) * 100
        : 0;
    const cls =
      divergence >= 15 ? 'critical' : divergence >= 5 ? 'warning' : 'info';

    await db
      .update(deterministicEngineRuns)
      .set({
        llmTotal: llmTotal.toFixed(2),
        divergencePercent: divergence.toFixed(2),
        divergenceClass: cls,
      })
      .where(eq(deterministicEngineRuns.projectId, projectId))
      .orderBy(desc(deterministicEngineRuns.id))
      .limit(1);

    return { divergence, divergenceClass: cls };
  }
  ```

## Critérios de aceite

- [ ] Para um memorial pequeno (Reforma Vânia REV08), o engine determinístico roda em paralelo aos agentes e termina em menos de 2 segundos.
- [ ] O resultado do engine é persistido em `deterministic_engine_runs` com todos os campos preenchidos.
- [ ] O Auditor recebe `deterministicTotal` e gera uma validação `deterministic_cross_check` com severidade adequada.
- [ ] Se a divergência é maior que 15%, o `auditSeal` resultante é `rejected` (a menos que outro critério já tenha rejeitado antes).

## Observações

- A primeira execução em produção provavelmente vai mostrar divergências grandes em obras antigas — isso é informação útil, não falha. Use os primeiros 30 dias como calibração antes de tornar a regra "critical >15%" bloqueante para a proposta.
- Considerar feature flag `ENABLE_DETERMINISTIC_VALIDATION=true` no `.env` para permitir desligar rapidamente em caso de problema sem precisar de hotfix.
- Após acumular dados, vale rodar análise de quais agentes/categorias de obra produzem maior divergência — isso vira backlog de melhorias específicas dos prompts.
- O engine determinístico tem suas próprias limitações (parser regex-based, sem inferência de qualidade). Não trate ele como "verdade absoluta" — trate como "segunda opinião".

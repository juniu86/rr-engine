# P0.5 — CI no GitHub Actions

**Prioridade:** P0
**Tipo:** chore
**Branch:** `chore/p0-5-ci-github-actions`
**Esforço estimado:** 0,5 dia
**Depende de:** —

## Objetivo

Habilitar execução automática de `pnpm test` e `pnpm check` em cada push e cada pull request via GitHub Actions. Sem CI, regressões nos 25 arquivos de teste existentes passam direto.

## Contexto

Hoje o repositório tem `vitest.config.ts` configurado para `server/**/*.test.ts` e 25 arquivos de teste. Não existe diretório `.github/workflows/`. Os testes só rodam quando alguém digita `pnpm test`. Esta é a primeira tarefa do plano de implementação porque destrava o restante: a partir do momento em que existe CI, todo PR seguinte ganha proteção automática.

## Arquivos a tocar

- `.github/workflows/test.yml` (novo)
- `.github/workflows/typecheck.yml` (novo)
- `package.json` — sem alteração estrutural; confirmar que os scripts `test` e `check` estão presentes (já estão na v3.1.0)
- `README.md` ou `CLAUDE.md` — adicionar badge de status do CI (opcional, ver tarefas)

## Tarefas

- [ ] Criar `.github/workflows/test.yml` com os passos: checkout, setup-node 20 LTS, setup-pnpm 10, `pnpm install --frozen-lockfile`, `pnpm test`. Triggers: `push` em qualquer branch e `pull_request` para `main`.
- [ ] Criar `.github/workflows/typecheck.yml` com os passos: checkout, setup-node, setup-pnpm, install, `pnpm check`. Mesmos triggers.
- [ ] Garantir que ambos workflows usam cache de pnpm (`actions/setup-node` com `cache: 'pnpm'`).
- [ ] Configurar `concurrency` para cancelar runs anteriores no mesmo PR (evita queue).
- [ ] Validar localmente com `act` ou em PR de teste que ambos workflows passam.
- [ ] (Opcional) Adicionar badge de status no `CLAUDE.md` no topo: `![CI](https://github.com/<org>/<repo>/actions/workflows/test.yml/badge.svg)`.

## Implementação sugerida

`.github/workflows/test.yml`:

```yaml
name: Test

on:
  push:
  pull_request:
    branches: [main]

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  test:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 10

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile

      - run: pnpm test
        env:
          NODE_ENV: test
```

`.github/workflows/typecheck.yml`:

```yaml
name: Typecheck

on:
  push:
  pull_request:
    branches: [main]

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  typecheck:
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 10

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile

      - run: pnpm check
```

## Critérios de aceite

- [ ] `.github/workflows/test.yml` existe e roda em pushes e PRs.
- [ ] `.github/workflows/typecheck.yml` existe e roda em pushes e PRs.
- [ ] Ambos workflows passam quando o branch é fresh fork de `main` sem alterações.
- [ ] Cache do pnpm está habilitado (validar pelo log do segundo run — deve ter "Cache restored").
- [ ] Os workflows finalizam em menos de 5 minutos no caso típico.
- [ ] Concurrency cancela run anterior quando um novo push acontece no mesmo PR.

## Testes

- Não há testes de código nesta tarefa. A validação é o próprio pipeline rodando verde no PR que introduz os workflows.
- Antes de mergear, validar que pelo menos um teste falha intencionalmente derruba o pipeline (commitar um teste com `expect(true).toBe(false)`, ver vermelho, reverter).

## Observações

- Não adicionar passo de deploy nesta tarefa. Deploy entra na fase de migração para fora do Manus.
- Se o repo precisar de secret para algum teste futuro (ex.: `ANTHROPIC_API_KEY`), adicionar via `Settings → Secrets and variables → Actions` no GitHub e referenciar como `${{ secrets.ANTHROPIC_API_KEY }}` apenas em jobs que precisam.
- Hoje os testes não exigem secrets. Se algum teste futuro precisar, ele deve ser marcado como skippable em CI sem a chave.

## Contexto

A Phase 3 do ticket P1.4 (scraping ativo de PINI/TCPO) ficou pendente porque a fonte oficial — TCPOWeb da Editora PINI — exige assinatura paga. Sem credencial autorizada, o Claude Code não pode implementar o scraping responsavelmente.

Hoje o produto roda com `PINI_DATABASE` estática (composições embarcadas) + cache no scraper de SINAPI via `orcamentor.com`. Funciona para os 30+ orçamentos já gerados. Vai funcionar até o produto ter primeiro cliente pagante exigindo cobertura PINI maior.

## Decisão a tomar

Três caminhos possíveis. A escolha afeta esforço e custo recorrente.

### Opção A — Assinatura TCPOWeb

Custo recorrente estimado: R$ 200-500/mês (verificar com a Editora PINI). Vantagem: fonte oficial, dados completos, atualização mensal estruturada. Desvantagem: contrato + custo fixo antes de receita.

### Opção B — Fonte alternativa autorizada

Investigar uso de fontes como CCB, IRENE-RJ, IBAPE-RJ ou tabelas regionais que sejam acessíveis e autorizadas. Vantagem: barato ou gratuito. Desvantagem: cobertura menor, atualização irregular, pesquisa toma tempo.

### Opção C — Continuar com base estática + scraping orcamentor

Mantém o estado atual. Atualiza manualmente quando a SINAPI publica nova revisão. Vantagem: zero custo. Desvantagem: dados envelhecem, e em algum momento o cliente vai cobrar transparência sobre a fonte.

**Recomendação default:** começar com C até primeiro cliente pagante validar willingness-to-pay. Migrar para A quando tiver MRR ≥ R$ 5.000 (ROI positivo da assinatura).

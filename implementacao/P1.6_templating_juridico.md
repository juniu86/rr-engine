# P1.6 — Templating estruturado para Jurídico

**Prioridade:** P1
**Tipo:** feat
**Branch:** `feat/p1-6-templating-juridico`
**Esforço estimado:** 3-4 dias
**Depende de:** P1.1 (Jurídico já em Sonnet)

## Objetivo

Substituir a geração livre de proposta no agente Jurídico por um sistema de template Markdown com slots preenchidos. A LLM passa a apenas (i) selecionar template adequado, (ii) preencher slots, (iii) gerar parágrafos curtos onde fizer sentido. O resultado é proposta com layout consistente e risco contratual reduzido.

## Contexto

Hoje o `JuridicoAgent` tem system prompt curto (~150 tokens) e produz `proposalText` como string livre — cada proposta sai com layout sutilmente diferente, e cláusulas críticas (foro, validade, prazo) podem aparecer com erro material. O risco é alto porque o documento vai para clientes externos.

Templating resolve dois problemas:
1. **Consistência de marca:** estrutura, ordem de cláusulas, formatação ficam previsíveis.
2. **Risco contratual:** cláusulas essenciais ficam com texto fixo revisado uma vez; só os slots dinâmicos (preço, prazo, escopo) variam.

## Template exemplo — `proposta_padrao.md`

```markdown
# Proposta Comercial — {{projectName}}

**Cliente:** {{clientName}}
**Data:** {{proposalDate}}
**Validade:** {{validityDays}} dias

## 1. Objeto

{{cl_objeto}}

## 2. Preço e Forma de Pagamento

Valor total: **R$ {{totalPrice|brl}}**.

{{cl_preco}}

{{cl_pagamento}}

## 3. Prazo de Execução

Prazo total: **{{durationDays}} dias** ({{durationWeeksLabel}}), contados a partir da assinatura do contrato.

{{cl_prazo}}

## 4. Garantias

{{cl_garantias}}

## 5. Responsabilidades das Partes

{{cl_responsabilidades}}

## 6. Confidencialidade

{{cl_confidencialidade}}

## 7. Rescisão

{{cl_rescisao}}

## 8. Foro

{{cl_foro}}

---

**RR Engenharia**
{{companyAddress}}
CNPJ: {{companyCnpj}}
```

Cada `{{cl_xxx}}` é resolvido pegando o conteúdo de `clausulas/xxx.md`. Cada `{{slot}}` simples é substituído por valor do input. Filtros (`|brl`, `|date`, etc.) formatam.

## Cláusula exemplo — `clausulas/objeto.md`

```markdown
A {{contratada}} se compromete a executar para o {{contratante}} os serviços de {{tipoObra}}, conforme escopo detalhado na memória de cálculo anexa, com base no memorial descritivo recebido em {{memorialDate}}.

{{?contractType=obra}}
A obra abrange {{escopoBreve}} no endereço {{enderecoObra}}.
{{/?}}

{{?contractType=manutencao}}
O contrato cobre serviços contínuos de manutenção predial nos termos da NBR 5674/2012.
{{/?}}
```

## Implementação — `juridicoTemplating.ts`

```ts
import { readFile } from 'node:fs/promises';
import { join } from 'node:path';

const TEMPLATES_DIR = join(__dirname, '..', 'templates', 'juridico');

export interface TemplateInput {
  projectName: string;
  clientName: string;
  proposalDate: string;
  validityDays: number;
  totalPrice: number;
  durationDays: number;
  contractType?: 'obra' | 'manutencao';
  contratada: string;
  contratante: string;
  tipoObra: string;
  memorialDate: string;
  escopoBreve?: string;
  enderecoObra?: string;
  companyAddress: string;
  companyCnpj: string;
  // ... outros slots
}

export async function renderProposta(
  templateName: 'padrao' | 'obra_publica' | 'manutencao',
  input: TemplateInput,
): Promise<string> {
  const file = templateName === 'padrao' ? 'proposta_padrao.md' : `variantes/${templateName}.md`;
  const raw = await readFile(join(TEMPLATES_DIR, file), 'utf-8');
  return await processTemplate(raw, input);
}

async function processTemplate(content: string, input: TemplateInput): Promise<string> {
  let result = content;

  // 1. Resolver includes de cláusulas {{cl_xxx}}
  const clauseMatches = [...result.matchAll(/\{\{cl_([a-z_]+)\}\}/g)];
  for (const match of clauseMatches) {
    const clauseName = match[1];
    const clauseContent = await readFile(
      join(TEMPLATES_DIR, 'clausulas', `${clauseName}.md`),
      'utf-8',
    );
    result = result.replaceAll(match[0], clauseContent);
  }

  // 2. Resolver condicionais {{?campo=valor}}...{{/?}}
  result = result.replace(/\{\{\?([a-zA-Z]+)=([a-zA-Z_]+)\}\}([\s\S]*?)\{\{\/\?\}\}/g, (_, field, value, body) => {
    return (input as any)[field] === value ? body : '';
  });

  // 3. Resolver slots simples e com filtros
  result = result.replace(/\{\{(\w+)(?:\|(\w+))?\}\}/g, (full, key, filter) => {
    const value = (input as any)[key];
    if (value === undefined || value === null) return full;
    if (filter === 'brl') return formatBRL(Number(value));
    if (filter === 'date') return formatDate(value);
    return String(value);
  });

  return result;
}

function formatBRL(n: number): string {
  return n.toLocaleString('pt-BR', { minimumFractionDigits: 2, maximumFractionDigits: 2 });
}

function formatDate(d: string | Date): string {
  const date = typeof d === 'string' ? new Date(d) : d;
  return date.toLocaleDateString('pt-BR');
}
```

## Reescrita do `JuridicoAgent`

O agente agora tem duas responsabilidades:
1. Selecionar template (`padrao`, `obra_publica`, `manutencao`).
2. Gerar slots dinâmicos curtos (`escopoBreve`, ajustes de redação).

```ts
export class JuridicoAgent extends BaseAgent<JuridicoInput, JuridicoOutput> {
  name = AGENT_NAMES.juridico;
  type: AgentType = "juridico";
  getPreferredModel() { return process.env.LLM_MODEL_INTERMEDIATE ?? "claude-sonnet-4-6"; }
  getTemperature() { return 0.2; }

  getSystemPrompt(): string {
    return `Você é o Agente Jurídico da RR Engenharia.

MISSÃO: Selecionar template de proposta e preencher campos descritivos curtos.

VOCÊ NÃO REDIGE A PROPOSTA. O texto base vem de templates aprovados.
Sua tarefa é:
1. Escolher o template apropriado (padrao | obra_publica | manutencao)
2. Preencher campos descritivos curtos como "escopoBreve" (1 frase descrevendo a obra)
3. Identificar cláusulas-extras necessárias se houver risco específico

NÃO inventar cláusulas. NÃO escrever cláusulas inteiras. Os templates já contêm o texto.`;
  }

  getOutputSchema(): object {
    return {
      type: "object",
      properties: {
        templateChoice: { type: "string", enum: ["padrao", "obra_publica", "manutencao"] },
        escopoBreve: { type: "string", description: "1 frase descrevendo o escopo" },
        clausulasExtras: { type: "array", items: { type: "object", properties: {
          title: { type: "string" }, content: { type: "string" }
        }, required: ["title", "content"] } },
        validityDays: { type: "number" },
      },
      required: ["templateChoice", "escopoBreve", "validityDays"],
      additionalProperties: false,
    };
  }

  // Override execute para combinar LLM + templating
  async execute(input: JuridicoInput): Promise<JuridicoOutput> {
    const llmOutput = await super.execute(input);

    const proposalText = await renderProposta(llmOutput.templateChoice, {
      projectName: input.projectName,
      // ... mapeamento de input
      escopoBreve: llmOutput.escopoBreve,
      // ...
    });

    const clauses = [
      ...DEFAULT_CLAUSES,           // ler dos arquivos clausulas/
      ...(llmOutput.clausulasExtras ?? []),
    ];

    return {
      proposalText,
      clauses,
      validityDays: llmOutput.validityDays,
      confidentialityTerms: '...', // preenchido pelo template
    };
  }
}
```

## Observações

- O texto base das cláusulas precisa ser revisado por advogado antes do primeiro uso. Esta tarefa é boa oportunidade para fazer essa revisão e oficializar.
- Manter os templates versionados no Git permite que mudanças jurídicas sejam revisadas como código. Considere adicionar workflow de aprovação: PRs em `server/templates/juridico/` exigem revisão extra.
- A LLM continua útil para casos especiais — ex.: cláusula adicional para obras com risco ambiental, condições específicas de licitação. O `clausulasExtras` no output cobre esses casos.
- Após estabilizar, considerar migração de Sonnet para Haiku 4.5 — a tarefa virou principalmente classificação + preenchimento de campo curto.

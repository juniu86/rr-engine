# P2.5 — Schema versionado de bases de preço

**Prioridade:** P2
**Tipo:** feat
**Branch:** `feat/p2-5-schema-bases-versionadas`
**Esforço estimado:** 3-4 dias
**Depende de:** P1.4 (já criou tabela `price_database_entries`)

## Objetivo

Aprofundar o que P1.4 começou: garantir que a tabela `price_database_entries` permite múltiplas versões da mesma composição (snapshots por data de referência), com mecanismo de rollback e visualização de histórico.

## Contexto

Em P1.4 foi criada a tabela com `referenceDate` e flag `isActive`. Esta tarefa amadurece o schema para suportar:
- Histórico de preços por composição (linha do tempo)
- Rollback se um refresh trouxer dados inconsistentes
- Visualização "qual era o preço SINAPI 87529 em janeiro/2025?"
- Comparação entre snapshots para identificar reajustes anormais

## Arquivos a tocar

- `drizzle/schema.ts` — adicionar tabela `price_database_snapshots` e ajustar relação
- `drizzle/<n>_price_snapshots.sql` — migration

## Schema adicional

```ts
export const priceDatabaseSnapshots = mysqlTable('price_database_snapshots', {
  id: bigint('id', { mode: 'number' }).primaryKey().autoincrement(),
  source: varchar('source', { length: 20 }).notNull(),
  state: varchar('state', { length: 5 }),
  snapshotDate: date('snapshot_date').notNull(),
  entriesCount: int('entries_count').notNull(),
  priceMin: decimal('price_min', { precision: 12, scale: 2 }),
  priceMax: decimal('price_max', { precision: 12, scale: 2 }),
  priceAvg: decimal('price_avg', { precision: 12, scale: 2 }),
  notes: text('notes'),
  triggeredBy: varchar('triggered_by', { length: 50 }), // 'cron', 'manual', 'rollback'
  rawDataS3Key: varchar('raw_data_s3_key', { length: 500 }), // backup completo em S3
  createdAt: timestamp('created_at').defaultNow().notNull(),
}, (t) => ({
  sourceDateIdx: index('idx_source_date').on(t.source, t.snapshotDate),
}));
```

A relação com `price_database_entries` é por `referenceDate` — entradas com a mesma referenceDate pertencem a um snapshot.

export async function getPriceHistory(
  source: 'sinapi' | 'pini',
  code: string,
  state?: string,
): Promise<Array<{ price: number; referenceDate: Date; scrapedAt: Date }>> {
  const conditions = [eq(priceDatabaseEntries.source, source), eq(priceDatabaseEntries.code, code)];
  if (state) conditions.push(eq(priceDatabaseEntries.state, state));

  const rows = await db.select({
    price: priceDatabaseEntries.price,
    referenceDate: priceDatabaseEntries.referenceDate,
    scrapedAt: priceDatabaseEntries.scrapedAt,
  })
  .from(priceDatabaseEntries)
  .where(and(...conditions))
  .orderBy(desc(priceDatabaseEntries.referenceDate));

  return rows.map(r => ({ price: parseFloat(r.price), referenceDate: r.referenceDate, scrapedAt: r.scrapedAt }));
}

export async function createSnapshot(
  source: 'sinapi' | 'pini',
  state: string,
  triggeredBy: string,
  notes?: string,
): Promise<{ snapshotId: number; entriesCount: number }> {
  // Busca entradas ativas
  const entries = await getActivePriceEntries(source, state);

  // Calcula estatísticas
  const prices = entries.map(e => parseFloat(e.price));
  const min = Math.min(...prices);
  const max = Math.max(...prices);
  const avg = prices.reduce((s, p) => s + p, 0) / prices.length;

  // (Opcional) salvar dump completo em S3 para rollback
  const s3Key = await uploadJsonToS3(`price-snapshots/${source}-${state}-${Date.now()}.json`, entries);

  const [snapshot] = await db.insert(priceDatabaseSnapshots).values({
    source,
    state,
    snapshotDate: new Date(),
    entriesCount: entries.length,
    priceMin: min.toFixed(2),
    priceMax: max.toFixed(2),
    priceAvg: avg.toFixed(2),
    notes: notes ?? null,
    triggeredBy,
    rawDataS3Key: s3Key,
  });

  return { snapshotId: snapshot.insertId, entriesCount: entries.length };
}

## Observações

- O dump em S3 é o backup definitivo. Banco mantém apenas metadata + entradas ativas. Em caso de perda total da tabela, snapshots permitem reconstrução.
- Considere política de retenção: manter todos snapshots no primeiro ano, depois apenas o último de cada mês. Reduz custo de S3.
- A UI de comparação ajuda a detectar comportamentos anômalos do scraper (ex.: site mudou layout e capturou descrições erradas — preços ficam inconsistentes).
- Versionamento permite outro recurso interessante: "orçamento histórico" — re-precificar um orçamento antigo com a base de hoje para ver quanto valeria atualmente. Não é prioritário, mas vale como ideia para roadmap.

# P1.5 — Bloquear fallback silencioso de `companyTaxSettings`

**Prioridade:** P1
**Tipo:** fix
**Branch:** `fix/p1-5-fallback-tax-settings`
**Esforço estimado:** 1 dia
**Depende de:** —

## Objetivo

Eliminar o fallback silencioso em `TributarioAgent.getUserPrompt()` que assume `lucro_presumido + ISS 5% + PIS/COFINS 3,65%` quando o usuário não configurou impostos. Em vez disso, falhar explicitamente — orçamento sem configuração tributária válida não pode ser gerado.

## Contexto

Em `server/agents/index.ts`, `TributarioAgent.getUserPrompt()` tem:

```ts
const taxSettings = (input as any).companyTaxSettings || {
  regimeTributario: 'lucro_presumido',
  issPercentual: 5.0,
  pisPercentual: 0.65,
  cofinsPercentual: 3.0,
  irpjPercentual: 1.2,
  csllPercentual: 1.08,
  taxaLeisSociais: 128.23,
};
```

Quando o usuário não configurou a empresa em Settings, o sistema usa esses valores **sem avisar**. O orçamento sai com tributos errados — uma empresa no Simples Nacional acaba pagando ISS de Lucro Presumido em todos os cálculos.

A correção é uma combinação de:
1. Validação na orquestração: se `companyTaxSettings` não existe, retornar erro estruturado para o usuário antes de chegar ao agente.
2. Aviso claro no frontend (Settings) quando a empresa não tem config.
3. Onboarding obrigatório para novos usuários.

Esta tarefa cobre os passos 1 e 2. O onboarding (passo 3) pode entrar em backlog separado de produto.

## Arquivos a tocar

- `server/routers.ts` — validar antes de chamar Tributário
- `server/agents/index.ts` — remover fallback do `TributarioAgent.getUserPrompt`
- `client/src/pages/Settings.tsx` — banner/badge quando config tributária é parcial
- `client/src/pages/NewProject.tsx` — bloquear botão "Gerar orçamento" se config faltar
- `server/storage.ts` — função `getCompanyTaxSettings(userId)` com validação
- `shared/types.ts` — tipo `CompanyTaxSettings` e função `isCompleteTaxSettings()`
- `server/settings.test.ts` — cobertura

## Tipo canônico

Em `shared/types.ts` (criar a seção se não existir):

```ts
export interface CompanyTaxSettings {
  regimeTributario: 'simples_nacional' | 'lucro_presumido' | 'lucro_real';
  issPercentual: number;
  pisPercentual: number;
  cofinsPercentual: number;
  irpjPercentual: number;
  csllPercentual: number;
  taxaLeisSociais: number;
  faixaSimples?: 1 | 2 | 3 | 4 | 5 | 6; // se Simples Nacional
}

export function isCompleteTaxSettings(s: Partial<CompanyTaxSettings> | null | undefined): s is CompanyTaxSettings {
  if (!s) return false;
  if (!s.regimeTributario) return false;
  if (s.issPercentual == null || s.issPercentual < 0) return false;
  if (s.pisPercentual == null || s.pisPercentual < 0) return false;
  if (s.cofinsPercentual == null || s.cofinsPercentual < 0) return false;
  if (s.regimeTributario === 'simples_nacional' && !s.faixaSimples) return false;
  return true;
}
```

## Observações

- Empresas existentes que já geraram orçamento sem config explícita continuam tendo o último orçamento válido — não há retroatividade. O bloqueio vale para projetos novos.
- A mudança no frontend é importante: bloquear na origem é melhor experiência que mostrar erro depois de o usuário escrever o memorial.
- Quando a faixa do Simples Nacional muda durante o ano (faturamento muda de faixa), o usuário precisa atualizar manualmente. Considerar em backlog: automação que sugere a faixa correta com base em faturamento informado.
